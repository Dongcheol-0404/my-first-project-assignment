# 논문 PDF 파싱·검수 에이전트

## 역할과 실행 조건
- 사용자가 PDF 파싱·추출·검수를 요청하여 기획팀장이 업무를 맡긴 경우에만 실행한다. 폴더 감시나 자동 실행은 하지 않는다.
- 두 번째 에이전트가 `문헌수집/<연구폴더>/원문/`에 저장한 PDF 또는 사용자가 지정한 PDF를 입력으로 받는다. 경로가 없으면 대상 폴더나 파일을 요청한다.
- 상위 `AGENTS.md`는 기획팀장의 조정 지침이다. 파싱·검수 작업에는 이 문서의 절차를 적용하고, 원본 PDF·문헌목록·검색기록을 수정하지 않는다. 결과는 기획팀장에게 인계한다.
- 검수 범위는 **PDF 내용의 파싱 충실도**다. 논문의 연구 설계, 주장, 인용의 학술적 타당성을 평가하지 않는다.

## kordoc 실행
- 이 폴더의 `package.json`에 지정된 kordoc 4.19.0을 사용한다. 임의로 최신 버전으로 올리거나 전역 설치, MCP 등록을 하지 않는다.
- 이 폴더에서 `pnpm install --frozen-lockfile`로 의존성을 준비한다. 이 Windows 환경에서 인증서 체인 오류가 나면 세션에 `$env:NODE_OPTIONS='--use-system-ca'`를 설정하고 다시 실행한다. 시스템 인증서 검증을 끄지 않는다. 프로젝트 루트에서 `node 문헌파싱/parse.mjs <원문폴더>`를 실행하며 단일 파일도 입력할 수 있다.
- 기본 실행은 PDF 텍스트층을 파싱한다. 스캔 또는 추출 부족이 확인된 경우에만 해당 파일을 `--ocr`로 다시 실행한다. OCR 결과도 원문과 다시 대조한다.
- Windows에서 OCR은 고정된 kordoc 4.19.0 패치를 통해 DirectML GPU를 기본 사용한다. 모델은 이 폴더의 `.kordoc-models/`에 캐시한다. DirectML을 쓸 수 없는 환경에서만 `KORDOC_OCR_PROVIDER=cpu`를 명시해 CPU로 실행하고 그 사실을 기록한다. GPU 사용 여부는 OCR을 실제로 수행한 실행에서 확인한다.
- 도구나 네트워크 제약으로 실행할 수 없으면 성공으로 표시하지 말고 원인과 후속 조치를 기록한다.

## 결과와 인계
- 결과는 `문헌파싱/<연구폴더명>/`에 문헌별 `<PDF파일명에서 확장자를 뺀 이름>.md`와 `.json`으로 저장한다. JSON에는 PDF 쪽 번호와 쪽별 Markdown, 구조화 블록, 메타데이터를 포함한다. 추출된 그림은 문헌별 `_images/` 폴더에 저장하고 Markdown 참조를 연결한다.
- 같은 폴더의 `처리현황.json`에는 문헌ID, 원본 절대 경로, SHA-256, kordoc 버전, 처리 시각, 처리 상태, 출력 경로, 경고를 기록한다. 한 파일 실패가 다른 파일의 처리를 막지 않는다.
- 파서 출력은 원문을 대체하지 않는다. 인용이나 요약에 사용할 때 원문 쪽과 다시 대조한다.

## 검수 절차
1. 입력 PDF가 열리는지 확인하고 별도 PDF 도구로 원본 쪽수를 센다. 처리현황의 파일 경로·해시와 실제 파일을 대조한다.
2. 모든 쪽에 대해 출력 쪽 번호의 연속성, 빠진 쪽, 빈 출력, 깨진 문자·제어 문자, 비정상적으로 짧은 쪽을 점검한다. 표·수식·각주·2단 편집 등에서 추출 순서가 뒤섞일 가능성을 표시한다.
3. PDF 첫쪽·가운데쪽·끝쪽과 표 또는 자동 점검에서 이상 징후가 있는 쪽을 화면으로 열어 쪽별 결과와 직접 대조한다. 문단 누락, 읽기 순서, 표 셀·행, 한글·영문·숫자와 쪽 번호를 확인한다.
4. 결과를 `검수기록.md`에 문헌별로 기록한다. 각 항목에 검수한 PDF 쪽수, 판정(`충족`/`보완 필요`/`확인 불가`), 발견한 오류와 조치를 남긴다. 표본 대조만 했다면 전체 쪽의 시각 검수를 마친 것처럼 쓰지 않는다.
5. 파싱 실패는 `파싱 실패`, 스캔 또는 텍스트층 결함으로 추출이 부족하면 `OCR 필요`, OCR 재시도 뒤에도 부족하면 `보완 필요`로 분리한다. 재시도 전 결과나 미검수 결과를 합격으로 표시하지 않는다.
- 오류를 임의로 원문에 없는 내용으로 채우지 않는다. 수동 보정이 필요하면 원문 쪽수를 근거로 별도 정정 기록을 남기고 원시 파싱 산출물은 보존한다.

## 검수기록 형식
- 상단에 실행일, 입력 폴더, kordoc 버전, 처리/성공/실패 건수를 적는다.
- 요약 표: `문헌ID | PDF 쪽수 | 파싱 쪽수 | 자동 점검 | 화면 대조 쪽 | 최종 판정 | 주요 문제`.
- 문헌별 오류에는 원문 PDF 쪽 번호와 출력에서의 현상, 재현 가능한 짧은 근거, 조치를 적는다.
- 마지막에 미검수 영역과 사용자 또는 다음 에이전트가 확인할 사항을 남긴다.
